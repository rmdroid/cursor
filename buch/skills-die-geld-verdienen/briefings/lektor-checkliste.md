# Lektor-Checkliste — Skills, die Geld verdienen

**Zielgruppe:** Geschäftsführung · IT-Leitung · Freiberufler  
**Genre:** Praxis-Fachbuch Mittelstand (keine Buzzword-Nebel, keine erfundenen Claims)  
**Stand:** 2026-09-07 · Lara · v1  
**Regel:** Gegenlesen erst nach Hans-Freigabe. Output je Kapitel: Änderungsliste + freigegebene Version.

---

## 1. Klarheit & Lesbarkeit (alle drei Leser)

- [ ] Erster Absatz sagt Nutzen/Entscheidung — kein Warmlaufen
- [ ] Sätze kurz; Fachbegriffe beim ersten Auftreten praxisnah erklärt (oder Glossar-Verweis)
- [ ] Kein Consultant-Deutsch, kein Hype („disruptiv“, „game-changing“, „KI-Revolution“)
- [ ] Beispiele konkret genug, dass ein Entscheider morgen handeln könnte
- [ ] Absätze scannbar (Zwischenüberschriften halten, was sie versprechen)

## 2. Drei-Rollen-Pfade (GF · IT · Solo)

Jedes Praxiskapitel prüfen:

- [ ] Abschlussblock vorhanden: *Was GF entscheidet / Was IT umsetzt / Was Solo morgen starten kann*
- [ ] GF-Pfad: Nutzen, Risiko, Ownership, Freigabe — ohne Technikdump
- [ ] IT-Pfad: Integration, Betrieb, Grenzen — ohne Konzern-Annahmen als Default
- [ ] Solo-Pfad: schlank (1–3 fokussierte Agenten), realistisch ohne Stab
- [ ] Keine Rolle wird mit „gilt für alle gleich“ abgespeist

## 3. Struktur & Redundanz

- [ ] Kapitelziel in 1–2 Sätzen erkennbar; passt zur Outline
- [ ] Keine Wiederholung von Kap. 1–3-Argumenten in späteren Kapiteln (Verweis statt Neuaufguss)
- [ ] Grafik-Briefings: klar, was gezeigt werden soll; Text hängt nicht von fehlender Grafik ab
- [ ] Steuerhebel bei Überlänge: Kap. 13 und 15 zuerst straffen (Alfred/Mara)

## 4. Skills & Verweise (ohne Code-Dumps)

- [ ] Kein SKILL.md-Rohcode, keine Prompt-Walls, keine Repo-Diffs im Fließtext
- [ ] Skill-Verweise zeigen auf kanonische GitHub-URL (Klaus) — Platzhalter „URL folgt“ flaggen
- [ ] Skill erklärt als wiederholbare Fähigkeit (Outcome, Input/Output), nicht als Magie
- [ ] Abgrenzung Chat / Assistent / Agent / Skill konsistent mit Kap. 1–2

## 5. Claims, Zahlen, Quellen → @Vera

- [ ] Jede Zahl/Quote hat Quelle oder ist klar als Muster/Beispiel markiert
- [ ] Verifiziert vs. Annahme vs. Unklar sichtbar (oder an Vera flaggen)
- [ ] Adoptions-/Marktquoten nicht vermischen (KfW ≠ Destatis ≠ Bitkom — andere Grundgesamtheit)
- [ ] EU-AI-Act: nur belastbare Anker; Fristen nicht aus Sekundärquellen erfinden
- [ ] Fehlende/schwache Claims: Liste an Vera, nicht stillschweigend glätten

## 6. Tonalität & Mandat

- [ ] Unternehmerton: direkt, fair-scharf, kein Vernichten, kein Abnicken
- [ ] Menschliche Grenze klar: Strategie, Geld, Recht, Personal, finale Freigabe bleiben beim Menschen
- [ ] Keine Rechtsberatung; keine Impressums-/Haftungsformulierungen erfinden
- [ ] Titel überall exakt: *Skills, die Geld verdienen* (kein alter Cover-Titel)

## 7. Lieferformat je Lektorat-Durchlauf

1. Kurze Einschätzung (1–3 Sätze): freigabefähig / mit Auflagen / zurück an Mara  
2. **Änderungsliste** (priorisiert: Blocker → Schärfung → Stil)  
3. **Freigegebene Kapitelversion** (MD, echte Umlaute)  
4. Offene Flags an @Vera (Quellen) bzw. @Klaus (Repo-Links) bzw. @Alfred (Scope)
