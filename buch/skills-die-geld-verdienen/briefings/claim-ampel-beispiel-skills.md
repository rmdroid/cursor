# Claim-Ampel — Beispiel-Skills (Steckbriefe)
Vera · 2026-09-07

Bezug: `briefings/beispiel-skills-steckbriefe.md`  
Regel: Grün = im Buch so sagbar · Gelb = nur mit Kennzeichnung · Rot = nicht behaupten

## Gesamt

| Claim-Typ | Ampel | Hinweis |
|-----------|-------|---------|
| Steckbriefe als **Muster** / Buch-Beispiele | 🟢 | Passt; Header „nicht aus privaten Repos“ beibehalten |
| ROI, Zeitersparnis %, „schließt Fachkräftelücke“ | 🔴 | Keine Quelle |
| KfW 20 % / Destatis 26 % als Beleg *für diesen Skill* | 🔴 | Belegen nur Adoption/NLG allgemein, nicht Skill-Outcome |
| „Skill verdient Geld“ als Methode/Entscheidung | 🟡 | Buchthese OK, nicht als empirische Studie verkaufen |
| NIST/Agent-Definition | 🟡 | Nur Anker; keine ISO/EU-Norm Chat≠Agent |

## Pro Steckbrief

### 1. `angebot-aus-kickoff`
| Aussage | Ampel |
|---------|-------|
| Wiederkehrender Mittelstands-/Solo-Schritt Kickoff→Angebot | 🟡 Muster (Cover-Logik), keine Fallstudie |
| Freigabe Preis/Scope/Risiko bleibt Mensch | 🟢 Betriebsregel (Kap. 2/5/6), kein Statistikclaim |
| Kein Versand / keine erfundenen Preise | 🟢 Designregel |
| Quantifizierter Nutzen | 🔴 |

### 2. `protokoll-entscheidungen`
| Aussage | Ampel |
|---------|-------|
| Protokoll mit Entscheidungen/Owner als wiederholbarer Outcome | 🟡 Muster |
| Keine Schein-Beschlüsse / kein Auto-Versand | 🟢 Designregel |
| Spracherkennung/NLG im Mittelstand häufig → „deshalb dieser Skill“ | 🔴 Kausalität unzulässig (KfW nur Technologie-Nutzung) |

### 3. `status-mandat-kurz`
| Aussage | Ampel |
|---------|-------|
| Statusentwurf mit Versand-Sperre bis Freigabe | 🟢 Designregel / Mandatsgrenze |
| Kundenvertrauen durch Automatik | 🔴 |
| Art.-50-Kennzeichnung wenn KI-Interaktion | 🟡 Kap. 6; im Steckbrief nicht überziehen |

## Viertes Muster (optional später)
**Recherche-Dossier mit Status Verifiziert/Annahme/Unklar** — Methode des Buchs; gut als viertes Muster, ebenfalls ohne ROI.

## Für Lara
Keine Quoten an Steckbriefe hängen. Adoption-Zahlen nur in Kap. 1/3 mit Methodenhinweis.
